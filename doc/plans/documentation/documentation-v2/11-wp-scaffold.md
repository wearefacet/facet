# WP 11 — Scaffold: tabs, moves, redirects, checks, rules

**Goal:** the new structure exists, every old page sits at its new path,
every old URL redirects, and the build enforces the v2 rules. Content stays as
it is (except front-matter and links); the content WPs rewrite it next.

**Depends on:** WP 10; decisions D1 (tabs), D2 (slugs), D4 (voice rules), D8 (French during the transition).
**Blocks:** all content WPs. Run this WP alone: nothing else may write under
`site-docs/` while it runs.

**Write scope:**

- `site-docs/astro.config.mjs`, `site-docs/package.json`,
  `site-docs/src/content.config.ts`
- every file under `site-docs/src/content/docs/` (moves, front-matter, link
  rewrites only — **no prose rewrites**)
- `site-docs/scripts/` (new checks)
- `scripts/gen_docs/` (only if a generator hard-codes a path that moved)
- `doc/site-docs.md`, `doc/documentation.md`
- `doc/plans/documentation/README.md` (one-line superseded notice)
- `doc/plans/documentation-v2/ledgers/originals/`

---

## Step 1 — Save originals of split and merged pages

Copy every old page whose action in `03-page-map.md` is `split` or `merge`
(English and French) to `doc/plans/documentation-v2/ledgers/originals/<old
path>`. These copies are read-only inputs for the content WPs.

## Step 2 — Tabs and sidebars

Install the sidebar-topics plugin (decision D1). Verify it supports the
installed Starlight version (`@astrojs/starlight` ^0.42) before you commit to
it; check its README and changelog. If it does not, use the fallback from D1:
five top-level sidebar groups, all collapsed except the current one.

The plugin lists topics above the sidebar, each with its own sidebar. Configure five topics: Discover (`/discover/`), Use (`/use/`), Build
(`/build/`), Administer (`/admin/`), Reference (`/reference/`). Each topic's
sidebar mirrors `02-information-architecture.md` §2.1–2.5, with nested
autogenerated groups per sub-directory and explicit labels (labels are the
group names in §2, sentence case). Groups below the current level are
`collapsed: true`.

The landing page (`index.mdx`) stays outside any topic.

## Step 3 — Move every page

For each row of `03-page-map.md` §1–§8, in English and in French:

1. `git mv <old> <new>` (create directories as needed). For `split`, move to
   the first target. For `merge`, move the first source to the target and
   delete the others only after Step 1 saved them. For `retire`, delete after
   Step 1.
2. Set front-matter: `type` from the map; `sidebar.order` per the map or the
   order in `02` §2; keep `title`, `description`, `audience`, `features`,
   `verified_at` unchanged (content WPs change them).
3. Create an empty stub for every new page in `03` §9 that is not blocked:
   front-matter only (`title`, `description: TODO`, `type`, `audience`,
   `features: []`, `draft: true`) and one line: `This page is being written.`
   Starlight's `draft: true` keeps stubs out of production builds.
   Create stubs for group `index.md` pages as needed so the sidebar groups
   render.

Use one commit per tab, so the history stays readable.

## Step 4 — Rewrite internal links

Every internal link (`/old/path/`) in every page (English and French) must
point to the new path. Write a small script that reads the map, rewrites
links, and reports links it could not resolve. Keep the script under
`site-docs/scripts/` for future moves.

## Step 5 — Redirects

Generate the Astro `redirects` block from the map (old → new, both locales,
trailing slash). Retired pages redirect to the replacement named in the map.
Keep the generated block in its own file (for example
`site-docs/redirects.mjs`) imported by `astro.config.mjs`, so it is easy to
extend.

## Step 6 — Schema and checks

1. `src/content.config.ts`: add `type: z.enum(['overview', 'tutorial',
   'how-to', 'explanation', 'reference'])`, required except on the landing
   page (make it optional in the schema and enforce in the check script, if
   Starlight's splash page needs it optional).
2. Add the internal link validator (`starlight-links-validator` or an
   equivalent; confirm Starlight 0.42 support). Dead internal links must fail
   the build.
3. Extend `scripts/check-coverage.mjs` (keep warn mode by default):
   - R2: every ID covered by at least one `how-to`/`tutorial`/`explanation`
     page, unless `reference-only: true`;
   - R5: non-overview pages with `features: []` are listed;
   - every page has a valid `type`;
   - titles longer than 40 characters are listed;
   - inventory rows marked `removed:` (WP 10) do not need coverage, and a
     page that cites one is reported like an unknown ID.
4. Wire the checks into `npm run build` the same way `check-coverage` runs
   today (prebuild, warn mode).

## Step 7 — Generators

Run `make gen-docs`. If a generator writes a link to a moved page, or
`feature_index.mjs` expects the old directory names, fix the generator, then
regenerate. Commit the regenerated pages.

## Step 8 — Durable rules

1. `doc/documentation.md`: add the v2 voice rules (from
   `01-voice-and-vibe.md` §3, §4.1–4.6, §5, §6, §10, §11) as a new **Rule 2b —
   Layers and onboarding**, and update the sentence-length rule. Keep it
   short: link `01-voice-and-vibe.md` only while this plan is active; the
   rules must stand on their own after the plan retires.
2. `doc/site-docs.md`: replace the **Information architecture** section with
   the five tabs, the page types, the redirects file, and the new checks.
3. `doc/plans/documentation/README.md`: add at the top: "Superseded for IA
   and voice by `../documentation-v2/`. Kept as history."
