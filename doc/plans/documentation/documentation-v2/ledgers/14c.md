   loopback callback with curl, see live log).

   The finished source lands in `site-docs/examples/brightwater/checkout-app/`

5. Try it locally (`pnpm dev` → `http://localhost:5173`) — sign in through
   Facet as Lucía; verified headless with the curl transcript (consent payload
   → code → token → app-token reads + manifest).
6. Deploy on Facet: set `host`, `pnpx @facetapp/cli login` + `deploy`;
   serving verified at `https://checkout-t3.apps.localhost:3443` on the
   throwaway, then cleaned up. CORS preflight from the hosted origin captured.

**Tutorial 5 — Connect an AI agent.** Reuses the 17b-verified MCP handshake
under the manager persona (Nadia — 17b verified admin/Ravi; the pairing here
is the manager role the plan names). Steps:

1. Nadia reads her MCP endpoint (`GET /Api/_mcp/endpoints`, or Settings →
   MCP endpoints in the browser — `use/account.md` documents that surface).
2. Connect: RFC 7591 dynamic registration (stateless — nothing to clean up
   afterwards), PKCE, consent driven with Nadia's session the way her browser
   would (curl + CSRF header + `role` + `resource`), token exchange.
3. Ask the question with a plain Node MCP client script (`tools/list`,
   `tools/call list_documents` on tents + bookings; the script cross-checks
   the date): "Which tents are free on 2026-12-13?"
4. Let the agent act: `tools/call create_document` — a draft booking that
   holds one free tent. This is the write whose audit row proves the
   governance story (reads leave no mutation row; a read-only demo would
   have nothing to show in the audit).
5. Read the trail: `GET /Api/Audit?filters[channel__eq]=mcp` as Ravi — the
   row carries `acting_role: iam.Roles.manager`; the login-event log carries
   Nadia's consent grant. Links `admin/history/audit.md`.
6. Clean up: delete the draft booking; the MCP registration is stateless
   (nothing to revoke); tokens expire in 15 minutes.
