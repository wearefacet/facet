## Friction points (findings for the docs and the maintainer)

1. **`state` is a reserved field name.** A doctype field called `state`
   collides with the system column; the booking status field is `status`.
   (Reserved: created_at, deleted_at, display_name, id, links, parent_id,
   search, state, updated_at, version.)
2. **`return` is a Lua keyword.** The natural action name "return" is not
   writable in a doctype script; the action is `mark_returned` and the event
   is `booking_returned`.
3. **Named-action events are past-tense verbs, not `updated`.** `confirm`
   emits `booking_confirmed` (default inflection), overridden by
   `event_name` where wanted. A hook's source events list must name those,
   or it never fires.
4. **Computed fields cannot bind in form views.** The booking `total`
   (data, computed) renders but the form view refuses it as a field.
5. **Composition needs the mutual `children` entry.** A child doctype with
   `member_of` alone is not enough; the parent declares the relationship
   under `children`, and the nested REST route uses the relationship name
   (`/Api/rentals/Booking/:id/lines`), not the child doctype name.
6. **Roles cannot live in domain files.** `iam.Roles` is an iam-domain
   doctype; the three business roles are created by `load.sh` through the
   API. This is the anticipated gap from the plan (finding for WP 16's
   "From dev to production" page).
7. **Accounts are created by CLI with an OTP.** `scripts/facet
   accounts:create` prints the one-time password on stdout; the first login
   answers `must_change_password` + `change_token`; the change-password call
   swaps the OTP for the real password. `load.sh` encodes this dance.
8. **Row scope loses to an unscoped read.** A role with both a
   `$my_clients`-scoped grant and an unscoped `read` on the same doctype
   sees everything — the unscoped grant defeats the scope. The sales role
   carries the scoped grant only. Worth a callout box in the row-scope page.
9. **Update guards cannot read pre-merge state** — discrepancy #17. The
   in-repair rule lives in the hook (which reads each item before writing).
10. **Auto-filed grants are narrower than a hook's runtime reads, and
    import-order dependent** — discrepancy #18. `ensure_grant` in load.sh
    widens to the full resource set and logs it.
11. **Hook runs in the OWNING domain.** Same-domain writes are direct;
    foreign reads need an active grant. Errors are collected (`ctx.error`)
    and logged as warnings; the rest of the booking still goes out.
12. **The webhook story from the 05 §3 sketch was dropped from the bundle.**
    No external HTTPS receiver exists on a dev instance to receive it; the
    webhook pages (WP 17 / 19) will tell that story with a receiver they
    control. Not a discrepancy — a scoping decision, recorded here.
13. **`filters[field__eq]=` in curl needs `-g`.** curl treats `[...]` as URL
    globbing and fails with exit 3; every curl in load.sh carries `-g`.
    Python's urllib is unaffected (seed.py).
14. **The dev watcher re-files nothing on boot when the producer is
    missing**, but its full rebuild does file tickets once both domains are
    live — which is why the rentals→equipment grant existed (Booking only)
    on the fresh path. Deterministic output needs the explicit grant step;
    that is `ensure_grant`.
