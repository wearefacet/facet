Un développeur client y cherche une route — ses méthodes, ses paramètres, ses
codes de statut — ou vérifie une forme d’erreur contre le code. La référence
intégrée ci-dessous couvre les routes des documents, de l’audit, de l’IAM, de
la plateforme, de l’import/export et des secrets.

Cette page intègre la référence interactive de l’API REST, produite à partir
de la spécification OpenAPI.
Le site embarque une copie de `doc/api/openapi.json`, servie à l’adresse
`/api/openapi.json`.
`make gen-docs-rest-api` actualise la copie depuis l’artefact versionné, qu’une
tâche de CI maintient synchronisé avec les routes.

Les guides pratiques sous `/build/apps/` présentent les mêmes routes avec des
exemples détaillés.

:::note
Le fichier OpenAPI couvre un sous-ensemble de la surface REST (la
fonctionnalité `PLT-12`) ; cette référence est donc partielle.
Le fichier dessert ces groupes de routes :

- CRUD des documents : lister, créer, lire, mettre à jour et supprimer les
  documents d’un doctype
- historique des documents, retour arrière et restauration, y compris les
  documents enfants
- liens entrants : les documents qui référencent un document
- le journal d’audit global et sa route de retour arrière
- les routes de comptes IAM : profil du compte courant, états des
  identifiants, mot de passe temporaire et invitation

Tous les autres groupes de routes — webhooks, fichiers, secrets, recherche,
WebSocket et authentification —
sont documentés dans les pages rédigées à la main sous `/build/apps/`.
:::
