Deux réglages de champ tiennent les valeurs sensibles à l’écart, et ils
résolvent deux problèmes différents. Un champ `secret` stocke une
information d’authentification dans un magasin chiffré à côté du document ;
le document ne porte qu’un marqueur. Un champ `write_only` accepte une
valeur, la remet au script, puis la jette.

## Quand l’utiliser

Utilisez un champ `secret` pour une valeur que le système doit conserver :
une clé API, un hachage de mot de passe, un jeton à usage unique. Utilisez
un champ `write_only` pour une valeur dont le script a besoin une fois et
que personne ne devrait garder, comme un mot de passe en clair que le
script hache.

| | Champ `secret` | Champ `write_only` |
| --- | --- | --- |
| Valeur conservée | Oui, chiffrée, en dehors des documents | Non, écartée après l’écriture |
| Visible à la lecture | Non, un marqueur seulement | Non, disparue après l’écriture |
| Visible dans l’historique, la recherche, les exports | Non | Non |
| Visible des scripts | Non, seulement le marqueur | Oui, pendant l’écriture |
| Modification et effacement | Oui, depuis la page détail | Sans objet |

## Avant de commencer

- **Un domaine de brouillon.** Vous modifiez le doctype dans un
  [domaine de brouillon](/fr/build/model/in-app/how-drafts-work/), ou dans
  le [dossier du domaine sur un serveur de développement](/fr/build/model/in-files/domain-files/).
- **Un mode.** Un champ `secret` déclare un `mode` : `hash` pour des valeurs
  seulement vérifiées, `sealed` pour des valeurs que le système doit relire
  lui-même, et `token` pour une valeur à usage unique générée par Facet.
- **Les limites.** Les secrets n’apparaissent jamais comme arguments
  d’actions, dans des tableaux ou des dictionnaires, ni dans les modèles de
  nom d’affichage et de recherche. Facet refuse sinon la définition.

## Étapes

<Tabs syncKey="build-mode">
<TabItem label="Builder">

1. Ouvrez le doctype dans le **Builder** et ajoutez un champ.
2. Choisissez le type **Secret** et sélectionnez le mode : **Vérification**,
   **Révélation** ou **Jeton à usage unique**. Un jeton demande sa durée de
   vie en secondes.
3. Pour une entrée en écriture seule, ajoutez un champ texte et cochez
   **Write only**.

</TabItem>
<TabItem label="Fichiers">

```yaml
# un doctype de service dans votre domaine (extrait)
fields:
  api_key:
    type: secret
    mode: sealed
    title: API key
  reset_code:
    type: secret
    mode: token
    ttl_seconds: 3600
  new_password:
    type: string
    write_only: true
    title: New password
```

</TabItem>
</Tabs>

### Règles par mode

| Mode | Usage | Clé supplémentaire |
| --- | --- | --- |
| `hash` | Vérifier une candidate contre la valeur stockée, sans jamais la relire. | — |
| `sealed` | Le système relit la valeur pour ses propres fonctions. | — |
| `token` | Facet génère la valeur ; un appelant la consomme une fois. | `ttl_seconds` (requis, un nombre positif de secondes) |

`min`, `max` et `pattern` sont admis sur un champ secret ; ils contrôlent le
texte en clair au moment où il est posé, pas le marqueur.

### Définir la valeur dans l’application

La page détail affiche un marqueur avec **Modifier** et **Effacer**. Une
modification prépare la nouvelle valeur : Facet la stocke et incrémente la
version du marqueur. Le mode `token` affiche **Générer un nouveau jeton** et
montre le jeton une seule fois.

### Fonctionnement d’un champ en écriture seule

Le script du doctype lit la valeur pendant l’écriture, fait son travail, et
Facet retire le champ avant que le document ne soit stocké. L’appariement
courant est un champ `read_only` de hachage : le script hache l’entrée en
écriture seule et y stocke le hachage, car un champ `secret` n’accepte que
des valeurs préparées.

## Exemple

Un petit registre de services dans un domaine d’exploitation façon
Brightwater :

```json
{
  "domain": "ops",
  "doctype": "Service",
  "aggregate_root": true,
  "schema_version": 1,
  "fields": {
    "name": { "type": "string", "required": true, "filters": ["equality", "text_search"] },
    "api_key": { "type": "secret", "mode": "sealed" },
    "reset_code": { "type": "secret", "mode": "token", "ttl_seconds": 3600 },
    "new_password": { "type": "string", "write_only": true }
  }
}
```

Un document stocké porte des marqueurs au lieu de valeurs :

```json
{
  "name": "Billing",
  "api_key": { "mode": "sealed", "version": 3, "set_at": "2026-03-01T09:12:00Z" }
}
```

Un secret effacé stocke `null`. Un champ `write_only` n’apparaît jamais dans
le contenu stocké.

## Dépannage

### L’écriture répond `422` sur le champ secret

Trois formes seulement sont valides : une poignée de préparation, un
marqueur, et `null` pour effacer. Une chaîne en clair dans le corps d’un
document est toujours refusée.

### Le jeton a été affiché une fois et est perdu

Les jetons s’affichent une fois, à la génération. Générez-en un nouveau ;
l’ancien jeton cesse de fonctionner.

### Un administrateur ne peut pas relire la valeur

C’est la conception. Aucune route ne renvoie une valeur scellée ou hachée.
Seules les fonctions du système propriétaires du champ la lisent, et une
valeur hachée n’est jamais lisible du tout. Pour la renouveler, posez une
nouvelle valeur ; la version du marqueur monte.

Les valeurs résident dans le magasin chiffré, indexées par document et par
nom de champ, en dehors des tables de documents. À la suppression d’un
document, le magasin garde ses emplacements jusqu’à la fin de la fenêtre de
rétention ; une tâche de maintenance les retire ensuite.

### La valeur en écriture seule est de nouveau nécessaire plus tard

Elle a disparu. Facet ne la stocke jamais. Conservez la source de la valeur
en dehors de Facet si vous en aurez de nouveau besoin.

:::caution
Le retour arrière d’un document vers un état antérieur ne restaure pas les
anciennes valeurs secrètes. Les valeurs actuelles restent en place, et les
anciennes informations d’authentification ne reviennent jamais.
:::
